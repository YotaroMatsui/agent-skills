# 意味レビュー規準

## 適用範囲

この規準は、決定的lintでは判定できない意味構造をレビューするために用いる。
表記ゆれ、句読点、見出し深さ、文字数の検査だけが目的の場合は、lintハーネスを先に用いてよい。

## レビュー単位

文書全体、節、段落、命題の順に固定する必要はない。
変更の影響が及ぶ最小単位から始め、依存が上位または下位へ延びる場合に範囲を広げる。

## 評価観点

### R1 知識契約

対象読者、目的、対象範囲、除外範囲、既知知識を識別できるか。
「完全」という表現が、宣言した境界を越えて一般化されていないか。

### R2 命題階層

主要命題、定義、根拠、例、例外、手順の役割を区別できるか。
上位層だけで全体像を把握し、必要に応じて下位層へ進めるか。

### R3 依存関係の閉包

主要命題に必要な用語、前提、根拠、条件、反証可能性へ到達できるか。
到達できない依存が、既知知識または未解決事項として明示されているか。

### R4 粒度整合

兄弟要素が同じ分類軸に沿っているか。
抽象概念と実装断片が、説明なしに同列へ置かれていないか。

### R5 局所的な情報予算

一つの節または段落が、一つの主要な問いに答えているか。
読者が離れた文脈を同時に保持しないと理解できない箇所がないか。

### R6 論証方向

前提から結論への接続を追跡できるか。
例が結論の証明として過大に扱われていないか。
条件、例外、代替解釈が、主張の強さに反映されているか。

### R7 構造投影

見出しと主題文から作った投影が、中心命題と主要な依存経路を保持するか。
投影だけでは見えない重要条件が、本文中で十分に近接しているか。

### R8 意味保存

修正によって、事実、仕様、条件、不確実性、引用、出典の意味が変わっていないか。
読みやすさのために必要な限定が削られていないか。

## 判定尺度

尺度は比較と改善のために用い、単純合算を品質の真値として扱わない。

- 3: 対象読者と目的に対して明確に成立している。
- 2: 利用できるが、局所的な改善余地がある。
- 1: 重要な欠落または混在があり、理解や判断を阻害する。
- 0: 成立していないか、評価に必要な情報がない。

## 所見の形式

所見は、抽象的な感想ではなく、位置、欠陥、影響、根拠、最小修正を含める。

```json
{
  "id": "SEM-R3-001",
  "location": "セクション名または行番号",
  "severity": "critical | major | minor | note",
  "dimension": "R1-R8",
  "claim": "閉包していない命題または構造上の問題",
  "missing_dependency": "不足する定義、前提、根拠、具体化または参照",
  "evidence": "本文または原資料から確認できる根拠",
  "impact": "対象読者の理解、判断、または意味保存への影響",
  "minimal_change": "意味を変えずに行う最小修正",
  "uncertainty": "レビュー判断の不確実性"
}
```

## 受入れの考え方

重大所見がないことだけでは受入れにならない。
少なくとも、主要命題の依存が閉じていること、構造投影が論証を保持すること、原資料との意味差分に重大な欠陥がないことを確認する。
未解消事項を許容する場合は、読者への影響と適用条件を明示する。

## LLMレビューの分離

起草とレビューに同じLLMを用いてもよいが、レビューでは原稿の自己弁護や隠れた推論を評価根拠にしない。
原資料、対象読者、知識契約、修正文、構造投影だけをレビュー入力にするのが望ましい。
高影響の文章では、人間の受入れまたは独立したレビュアーをDecision Gateとして設ける。
